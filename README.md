# auto-naver-blog

사진과 강조할 내용, 카테고리를 입력하면 `claude` CLI 가 이미지를 분석해 블로그 글을 쓰고,
Aside 브라우저로 네이버 블로그 스마트에디터에 채워 넣은 뒤 — **사람이 미리보기를 승인해야만**
— 발행하는 로컬 단일 사용자 웹서비스다. 첫 번째 이미지가 대표(썸네일) 이미지가 된다.

## 라이브 검증 상태

`lib/naver/**` 는 **실제 네이버 스마트에디터에 대해 검증됐다** (2026-08-25). 글 하나를
끝까지 발행해 확인했다 — 에디터 진입, 제목·본문 입력, 사진 업로드(네이버 CDN 반영 확인),
대표 이미지, 카테고리 선택, 태그, 미리보기 스크린샷, 발행, 발행된 글 주소 회수까지.

검증에서 드러난 실제 구조는 `lib/naver/selectors.ts` 각 상수 위에 근거와 함께 적혀 있다.
초기 가설과 달랐던 것들:

- **카테고리·태그·공개설정은 본문 화면에 없다.** 툴바의 '발행' 을 눌러야 열리는 발행 설정
  패널 안에 있다. 그래서 단계 순서가 `제목 → 본문·사진 → 발행 패널 열기 → 카테고리 →
  태그 → 미리보기` 다. 패널을 열어 둔 채 멈추므로 안전 계약은 그대로다.
- **사진 추가는 DOM 의 file input 이 아니라 네이티브 파일 선택창**을 연다 —
  `page.waitForEvent('filechooser')` 로 받아야 한다.
- **Aside 는 세션 디렉터리 밖의 파일을 읽지도 쓰지도 못한다.** 업로드할 이미지와 미리보기
  스크린샷을 세션 디렉터리(`pwd`)를 거쳐 주고받는다.
- **대표(썸네일) 이미지는 첫 번째 사진이 기본값**이라 따로 지정할 필요가 없다.
- **장소 검색창은 react-autosuggest** 라 키보드 타이핑으로는 한글이 첫 글자만 들어간다
  (`판교역` → `판`). `locator.fill()` 로 값을 한 번에 넣어야 하고, Enter 가 아니라 전용
  검색 버튼을 눌러야 검색이 걸린다. 결과의 '추가' 버튼은 hover 전에는 클릭 가능 판정을
  통과하지 못해 DOM 클릭으로 누른다.
- **본문은 진입할 때 한 번만 클릭해 캐럿을 잡아야 한다.** 조각마다 다시 클릭하면 클릭
  지점이 문단 중간에 떨어져 글이 뒤엉킨다.

네이버가 UI 를 바꾸면 아래로 어느 단계가 깨졌는지 바로 확인할 수 있다 (claude 를 부르지
않아 비용이 들지 않는다):

```bash
npm run e2e:editor                 # 미리보기까지만 — 발행하지 않는다
E2E_PUBLISH=1 npm run e2e:editor   # 실제로 발행까지 한다
```

절차 문서는 [`docs/naver-live-validation.md`](docs/naver-live-validation.md) 를 참고한다.

## 아키텍처

- `lib/aside` — Aside 브라우저와의 REPL 채널(`AsideRepl`), 네이버 로그인 세션(`NaverSession`)
- `lib/content` — 이미지 분석과 초안 생성 (`ContentGenerator`, `claude` CLI 호출)
- `lib/naver` — 스마트에디터 조작 (`NaverPublisher`) — 위 경고 참고
- `lib/job` — 잡 상태 저장소와 API 라우트가 쓰는 서비스 주입 지점 (`setServices`/`getServices`)
- `lib/aside/login-flow.ts` — 로그인 절차(창 열기 → 사람 로그인 대기 → 쿠키·블로그 정보 저장).
  CLI(`npm run naver:login`)와 웹 온보딩 화면이 같은 코드를 쓴다
- `lib/aside/blog-meta.ts` — 블로그 아이디·카테고리 추출과 `.env` 기록/읽기, 온보딩 상태 판정
- `app` — 온보딩, 업로드 UI, 잡 상태 폴링, 미리보기·발행 승인 화면
- `lib/pipeline` — 위 조각들을 실제로 조립하고 Aside REPL 의 지연 시작·정리를 담당
- `instrumentation.ts` — Next.js 서버 부팅 훅. `lib/pipeline` 이 만든 서비스를 주입하고,
  프로세스 종료 시 정리한다

## 최초 설정

```bash
npm install
npm run setup        # aside·claude 실행 가능 여부, data/ 준비, 쿠키 존재 여부를 점검하고 안내한다
npm run naver:login   # Aside 브라우저에서 직접 로그인한다 (자동 로그인 아님, 사람이 함)
```

### 온보딩

`npm run dev` 로 서버를 띄우고 화면을 열면, 로그인 전에는 업로드 폼 대신 **온보딩 화면**이
뜬다. 거기서 "네이버 로그인 시작"을 누르면 아래 CLI 와 **같은 절차**(`lib/aside/login-flow.ts`)
가 서버에서 돌아간다 — Aside 브라우저에 창이 열리고, 사람이 직접 로그인하면 쿠키와 블로그
정보가 저장된 뒤 업로드 화면으로 넘어간다. 온보딩 상태는 `.env` 파일과 쿠키 파일을 직접 읽어
판정하므로 서버를 다시 띄울 필요가 없다.

업로드 화면에서 **장소**를 선택 입력할 수 있다. 적으면 에디터의 '장소' 검색으로 찾아 글 맨
끝에 **지도 블록**으로 붙는다 — 검색 결과가 여러 건이면 가장 위 1건을 고르고, 결과가 하나도
없으면 팝업만 닫고 장소 없이 그대로 발행한다(실패로 보지 않는다). 초안(LLM)이 아니라 사용자가
적은 값으로 검색하므로 상호명이 지어내질 여지가 없다. 비워 두면 장소 단계를 건너뛰고,
프롬프트도 그 경우 위치·상호를 언급하지 말라고 지시한다.

초안의 문체는 실제 네이버 블로그 글 두 편을 분석해 `prompts/post-draft.md` 에 반영했다 —
짧게 끊고 자주 줄바꿈, 존댓말 구어체, 독자에게 말 걸기, 감탄 표현 절제. 말투만 바꾼 것이며
"과장 금지 / 사실 날조 금지" 규칙은 그대로 전부 적용된다.

카테고리는 로그인할 때 읽어 둔 목록에서 **드롭다운으로 고른다** — 이름을 손으로 적어
블로그의 실제 카테고리와 어긋나는 일을 막기 위해서다. 목록이 비어 있으면 직접 입력으로
폴백한다.

### CLI

### 로그인은 한 번만 — '로그인 상태 유지'

네이버는 **'로그인 상태 유지'를 켜지 않으면 인증 쿠키(`NID_AUT`)를 만료일 없는 세션 쿠키로**
내려준다. 그러면 브라우저를 닫는 순간 로그인이 풀리고, 저장해 둔 쿠키를 복원해도 서버 세션이
이미 끝나 소용이 없다(실측: 이틀 만에 끊겼다).

그래서 로그인 페이지를 열 때 그 체크박스를 **자동으로 켠다**. 자격증명이 아니라 화면의 설정
토글이라 대신 눌러도 안전 계약에 어긋나지 않는다 — 아이디·비밀번호는 여전히 사람이 직접
입력한다. 로그인 후에는 인증 쿠키가 실제로 영속인지 확인해서 알려준다:

```
로그인이 유지됩니다 (인증 쿠키 만료: 2027-...). 다시 로그인하지 않아도 됩니다.
주의: 인증 쿠키가 세션 쿠키입니다 — 브라우저를 닫으면 로그인이 풀립니다.
```

이미 로그인된 상태에서는 체크박스를 건드릴 수 없다. 그래서 화면 위쪽에 **"다시 로그인"**
버튼이 뜬다 — 누르면 저장된 쿠키를 지우고 네이버에서 로그아웃한 뒤 로그인 화면부터 다시
시작한다.

브라우저에서 그냥 로그아웃하는 것만으로는 부족하다: 이 앱의 로그인 확인은 저장해 둔 쿠키를
브라우저에 **복원**하기 때문에, 로그아웃해도 곧바로 다시 로그인된 상태가 된다(실측 —
로그아웃했는데 온보딩이 뜨지 않았던 이유다).

### 로그인이 살아 있는지 확인하는 방식

`GET /api/setup` 은 파일(쿠키 파일·`.env`)만 보고 즉시 답한다. 파일만으로는 브라우저에서
로그아웃했는지 알 수 없으므로, 화면은 뜬 직후 `GET /api/setup?verify=1` 로 **실제 로그인이
살아 있는지 한 번 더 확인한다**(Aside 로 네이버에 다녀오므로 몇 초 걸린다). 확인에 실패하면
업로드 화면 대신 온보딩이 뜬다.

`naver:login` 은 Aside 브라우저에 "내 블로그"를 연다. 이미 로그인돼 있으면 로그인 단계를
건너뛰고, 아니면 로그인 페이지로 튕기므로 그 자리에서 직접 로그인하면 된다(5분 대기).
로그인이 확인되면 쿠키를 저장한 뒤 **블로그 아이디와 카테고리 이름 목록을 읽어 `.env` 에
기록한다** (`NAVER_BLOG_ID`, `NAVER_BLOG_CATEGORIES`). 기존 `.env` 의 다른 키와 주석은
보존된다.

업로드 화면에서 입력하는 카테고리 문자열은 블로그의 실제 카테고리 이름과 정확히 일치해야
한다 — `.env` 에 기록된 `NAVER_BLOG_CATEGORIES` 로 확인할 수 있다.

```bash
npm run dev            # http://127.0.0.1:3000
```

## 안전 계약

- 발행은 오직 `POST /api/jobs/[id]/publish` 로만 시작되고, 그 엔드포인트는 잡의 phase 가
  `awaiting_approval` 일 때만 동작한다 — 즉 사람이 채워진 에디터의 스크린샷 미리보기를 보고
  승인해야만 발행 버튼이 눌린다. 초안 생성이나 에디터 채우기 단계에서 자동으로 발행되는
  경로는 없다.
- 로그인은 항상 사람이 Aside 브라우저 창에서 직접 한다 (`npm run naver:login`). ID·비밀번호를
  코드나 환경변수로 다루는 곳은 없다.

## 알려진 제약

- 로컬 단일 사용자용이며 인증이 없다 — 반드시 루프백(`127.0.0.1`)에만 바인딩해서 쓴다
  (`npm run dev`/`npm start` 는 이미 `-H 127.0.0.1` 로 고정돼 있다).
- 한 번에 최대 20장의 이미지까지 지원한다.
- `claude` CLI 호출마다 비용이 발생한다.
